What the two non-exact oracle results contained

T2.4: correct regions, with additional actual/target/attainment columns. T3.4: correct shares, but missing the oracle’s raw revenue column. Exact-shape matching distinguishes these from identical outputs.

Where the model still failed

T4.2 · fail: interpreted “last month” as February, with 0.93 confidence, instead of using the latest available March or clarifying. T4.11 · partial: chose the expected city but divided by one month’s target (10,000), instead of all three months (28,500).

The prompt was 20,039 characters. Runs used two keys sequentially after the first reached its token quota. There was one attempt per question; no repeat-run distribution or pinned prompt/commit snapshot is saved. A near-match to holdout T2.5 appears among curated examples, so the holdout does not demonstrate strong generalization.

WHAT THE CAMPAIGN CHANGED

Failures became explicit rules.

Business definitions

Explicit revenue, AOV, percentage and target-join rules; dates grounded in available data; rankings include the metric supporting the answer.

Execution boundaries

The early DELETE failure motivated code-level read-only checks. The current system adds SQLGlot allowlists, disabled external access, bounded output and interrupt timers.

Better measurement

Normalize numeric scalar strings, distinguish table shape from values, and separate oracle comparison from manually reviewed behavior.

Reproduce the checks

Offline checks require no key and make no provider calls:

uv run --no-group evaluation python -m unittest discover -s tests -p 'test_*.py' -v
uv run --no-group evaluation python -m scripts.benchmark --runs 5

A deliberately invoked live sample requires a running app and a configured Groq key; it consumes provider quota:

uv run python -m tests.eval.run_groq_eval --ids T1.1 T2.3

The optional Gemini judge is separate tooling with separate credentials and quota. Live runs should pin the model, prompt and dataset and review generated SQL as well as output values.
