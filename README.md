# Intelligent Analytics Query Engine

A natural language → SQL → DuckDB analytics engine with a modern chat UI.

Ask questions about your sales and targets data in plain English, and get
instant results powered by Groq LLM inference and DuckDB.

## Architecture

```
User (Chat UI)  →  FastAPI  →  Groq LLM  →  DuckDB  →  Results
                      ↕                        ↕
                 feedback_log.csv         CSV datasets
```

## Quick Start

### 1. Prerequisites

- Python 3.10+
- [uv](https://docs.astral.sh/uv/) package manager
- A [Groq API key](https://console.groq.com)

### 2. Setup

```bash
# Install dependencies
uv sync

# Create your .env file
cp .env.example .env
# Edit .env and add your GROQ_API_KEY

# Run the data preprocessing pipeline
uv run python scripts/preprocess.py
```

### 3. Run

```bash
uv run python main.py
```

Open [http://localhost:8000](http://localhost:8000) in your browser.

## Features

- **Self-correction loop**: Failed SQL is fed back to the LLM for up to 3 retry attempts
- **Feedback learning**: User thumbs up/down are logged and injected into future prompts
- **Confidence scoring**: Each response includes a color-coded confidence badge
- **Collapsible SQL**: View the generated SQL and reasoning for each answer
- **Response cache**: Repeated questions reuse a successful answer from a
  128-entry in-memory LRU cache. The key includes the question, prompt,
  model settings, and the loaded CSV snapshot. Responses over 256 KiB and
  failed requests are not cached. `cache_hit` in the API response shows reuse.
  Whitespace differences are ignored; differently worded questions generate
  a new answer.

## Evaluation

Run local regressions with `.venv/bin/python -m unittest discover -s tests -p 'test_*.py'`.
The full model evaluation in `tests/eval/run_eval.py` requires a running API,
Groq access, and Gemini judge keys. Its Tier 4 behaviour scores use an LLM
judge, so review those traces alongside the numeric summary.
If Gemini judging is unavailable, run `uv run python -m tests.eval.run_groq_eval`
against the running API. It scores oracle cases locally, saves every response
for manual review, and restores the feedback log after the run.
